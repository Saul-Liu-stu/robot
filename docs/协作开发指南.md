# 协作开发指南

> 本工程采用 **一人一仓库（Fork + Pull Request）** 模式协作。
> 主仓库：<https://github.com/Saul-Liu-stu/robot>

## 1. 协作模式说明

- **主仓库**（Saul-Liu-stu/robot）：只有维护者有写权限，是唯一"正式"代码
- **个人仓库**：每个队友 Fork 一份，在自己的仓库自由开发
- 代码要进主仓库，必须通过 **Pull Request（PR）**，由维护者审核后合并
- 好处：主仓库 main 分支永远是可编译、可运行的代码

```
主仓库 (Saul-Liu-stu/robot)   ←— 收 PR、合并
        ↑ Fork                      ↑ 发 PR
个人仓库 (队友/robot)        ←— 队友日常开发、push
```

## 2. 新队友一次性设置

1. 打开主仓库页面 → 右上角 **Fork**，创建自己的副本
2. 克隆自己的仓库：

```bash
git clone https://github.com/<你的用户名>/robot.git
cd robot
```

3. 关联主仓库（用于同步别人的最新代码）：

```bash
git remote add upstream https://github.com/Saul-Liu-stu/robot.git
git remote -v   # 确认 origin 指向自己的仓库，upstream 指向主仓库
```

4. 配置身份（首次使用 git 时需要）：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

## 3. 日常开发流程（按顺序执行）

```bash
# ① 开工前：同步主仓库最新代码
git checkout main
git pull upstream main
git push origin main

# ② 开新分支开发（不要在 main 上直接改）
git checkout -b feat/功能名

# ③ 开发、编译、调试，提交
git add .
git commit -m "feat: 描述这次改了什么"

# ④ 推送到自己的仓库
git push -u origin feat/功能名
```

5. 到 **自己的仓库** GitHub 页面 → **Compare & pull request** →
   目标选 `Saul-Liu-stu/robot` 的 `main` 分支 → 填写改动说明 → 提交 PR
6. 维护者 Review 后合并；若被要求修改，继续提交并 push 到同一分支，PR 会自动更新

## 4. 维护者操作

- 收到 PR 后在 GitHub 上查看改动、评论，确认无误后 **Merge**
- 合并后通知队友执行第 3 节第 ① 步同步

## 5. 从别人仓库搬代码

队友还没提 PR、但你需要他某个提交时：

```bash
# 一次性添加队友仓库为远程
git remote add <队友名> https://github.com/<队友用户名>/robot.git
git fetch <队友名>

# 精确搬运某个提交到当前分支
git cherry-pick <提交哈希>
```

## 6. 提交信息规范

格式：`类型: 描述`（中文描述）

| 类型 | 用途 |
|------|------|
| feat | 新功能 |
| fix | 修 bug |
| docs | 文档 |
| refactor | 重构（不改变行为） |
| test | 测试相关 |

示例：`feat: 实现对角小跑步态`、`fix: 修复 IMU 初始化失败`

## 7. 冲突处理

`git pull upstream main` 或 PR 合并时提示冲突，按以下步骤解决：

1. 打开冲突文件，找到 `<<<<<<<` / `=======` / `>>>>>>>` 标记
2. 与队友沟通，保留正确代码，删除所有标记
3. `git add 冲突文件` → `git commit`
4. 重新 push

## 8. 工程特有约定

- **`.ioc` 文件**：改 CubeMX 硬件配置前先同步（第 3 节第 ① 步），改完当天提交 PR，避免冲突
- **编译产物**：`Debug/`、`QT_APP/build_apk/`、APK 等已被 `.gitignore` 排除，不要强制添加
- **main 分支**：主仓库 main 必须保持可编译
- **编码**：文件统一 UTF-8（含中文文件名）
- **任务分工**：在 GitHub Issues 里创建任务并指派，避免私下口头约定
