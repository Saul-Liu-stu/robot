# Qt 蓝牙上位机架构设计笔记

> 适用场景：通过经典蓝牙 SPP 与 MCU 通信、需要处理多版本协议的 Qt Android App

---

## 1. 分层架构：每层只做一件事

```
┌─────────────────────────────────────┐
│  mainwindow      UI 层              │  只管布局 + 信号连接
│  servowidget / pidwidget            │  只管展示 + 用户交互
├─────────────────────────────────────┤
│  bluetoothclient  蓝牙传输层         │  只管连接 + 收字节 + 发字节
├─────────────────────────────────────┤
│  protocol_core    协议解析层         │  纯函数，无状态，无 Qt 依赖
└─────────────────────────────────────┘
```

**核心原则：下层不知道上层存在。** `protocol_core` 不知道谁在调用它，`bluetoothclient` 不知道 UI 长什么样。

---

## 2. 多协议共存：加新不加删，前缀分流

三种协议写三个独立解析函数，互不覆盖：

```cpp
// 协议层 — 每阶段一个函数，互不干扰
ServoResponse  parseServoLine(line);      // 阶段一：舵机校准
PidMessage     parsePidLine(line);        // 阶段二：PID 调参
int            parseTelemetryLine(...);   // 阶段三：步态+IMU（未启用）
```

**传输层按前缀排队分发，不匹配就跳过**：

```cpp
void processBuffer() {
    // 阶段一：舵机 — 首字符 "S" 或 "O"
    ServoResponse sr = parseServoLine(line);
    if (sr.event != None) { emit servoXxx(sr); return; }

    // 阶段二：PID — 数字/负号/字母
    PidMessage pm = parsePidLine(line);
    if (pm.type != PidNone) { emit pidXxx(pm); return; }

    // 阶段三：IMU — 首字符 "R" 或 "A"
    TelemetryData td;
    if (parseTelemetryLine(line, &td)) { emit telemetryReceived(td); return; }
}
```

**为什么不会串：** 三种协议的首字符天然互斥

| 协议 | 首字符 | 示例 |
|------|--------|------|
| 舵机 | `S` `O` | `Servo Calib Ready` `OK:135` |
| PID | 数字 `-` `P` `K` `T` `G` `S` | `58,60,45` `Kp=5` `GO` |
| IMU | `R` `A` | `R:1.5 P:-0.3 Y:45.2` `A:12345/...` |

## 3. UI 页面切换：QStackedWidget + 握手信号

```cpp
// 构造时预建所有页面，不删不重建
m_stack = new QStackedWidget;
m_stack->addWidget(m_servoWidget);  // index 0
m_stack->addWidget(m_pidWidget);    // index 1
m_stack->setCurrentIndex(1);        // 默认显示 PID

// 连接后根据握手自动切页
connect(m_bt, &BluetoothClient::pidReady,   this, [this]() { m_stack->setCurrentIndex(1); });
connect(m_bt, &BluetoothClient::servoReady, this, [this]() { m_stack->setCurrentIndex(0); });
```

**好处：** 无论连什么固件，自动识别，无需用户手动切模式。

## 4. 命令发送：让 UI 只关心语义

PID 面板只发信号 `commandRequested("P+")`，不关心底层怎么编码：

```cpp
// pidwidget.cpp — UI 层：只管用户意图
connect(btn, &QPushButton::clicked, this, [this]() {
    emit commandRequested("P+");    // 纯语义
});

// mainwindow.cpp — 桥接层：路由到传输层
connect(m_pidWidget, &PidWidget::commandRequested, this, [this](const QString &c) {
    m_bt->sendPidCmd(c);   // "P+" → "P+\r\n" → write()
});

// protocol_core.cpp — 协议层：负责编码
QByteArray buildPidCmd(const QString &cmd) {
    return cmd.toUtf8() + "\r\n";   // "P+" → "P+\r\n"
}
```

三层各司其职：
- `pidwidget` 不知道有 `\r\n`
- `mainwindow` 不知道编码细节
- `protocol_core` 不知道谁在调用

## 5. 文件保存：QFileDialog 自动跨平台

```cpp
void onExportCsv() {
    // 一行代码，Android 调 SAF，Windows 弹原生对话框
    QString path = QFileDialog::getSaveFileName(
        this,
        "导出 CSV",           // 标题
        "servo_calib.csv",    // 默认名
        "CSV (*.csv)"         // 类型过滤
    );
    if (path.isEmpty()) return;  // 用户取消

    // 拿到路径后就是标准 Qt 写文件
    QFile f(path);
    if (f.open(QIODevice::WriteOnly | QIODevice::Text)) {
        QTextStream out(&f);
        out << "Servo,Angle\n";
        for (int i = 0; i < 12; i++)
            out << "S" << (i+1) << "," << m_savedAngles[i] << "\n";
        f.close();
    }
}
```

**思路：** Qt 帮我处理平台差异，我只管读写字节能打开的文件路径。

## 6. Android 蓝牙 JNI：照抄能跑的模式

核心三板斧，来自已验证可运行的参考工程：

```cpp
// ① JNI 引用用 void* 存，QJniObject 临时构造
void *m_javaSocket = nullptr;     // BluetoothSocket 全局引用
void *m_outputStream = nullptr;   // OutputStream 全局引用

// ② 连接：先反射 channel=1，失败回退 SPP UUID
bool connectRfcomm(const QString &address) {
    QJniObject adapter = QJniObject::callStaticObjectMethod(
        "android/bluetooth/BluetoothAdapter", "getDefaultAdapter",
        "()Landroid/bluetooth/BluetoothAdapter;");
    // ... 获取 Device → 反射 createRfcommSocket(1) → connect() →
    // 回退 createRfcommSocketToServiceRecord(SPP_UUID)
}

// ③ 后台线程读流
class RfcommReader : public QThread {
    void *m_inputStream;    // void* 存全局引用
    void run() override {
        QJniObject is(static_cast<jobject>(m_inputStream));  // 临时构造
        while (m_running) {
            jint n = is.callMethod<jint>("read", "([B)I", jbuf);
            // ... emit dataReceived(chunk) → 主线程处理
        }
    }
};
```

**为什么用 void\* 而不是 QJniObject 成员：** `QJniObject` 析构时会自动释放本地引用，但读写线程需要的是全局引用。用 `void*` 显式管理全局引用的生命周期，不容易出错。

## 7. CMakeLists.txt：极简模板

```cmake
cmake_minimum_required(VERSION 3.16)
project(MyApp VERSION 1.0 LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_AUTOMOC ON)                    # 关键：自动处理 Q_OBJECT

find_package(Qt6 REQUIRED COMPONENTS Core Widgets Bluetooth)

qt_add_executable(MyApp
    main.cpp
    protocol_core.h    protocol_core.cpp
    bluetoothclient.h  bluetoothclient.cpp
    mainwindow.h       mainwindow.cpp
)

target_link_libraries(MyApp PRIVATE Qt6::Core Qt6::Widgets Qt6::Bluetooth)

if(ANDROID)
    set_target_properties(MyApp PROPERTIES
        QT_ANDROID_MIN_SDK_VERSION 26
        QT_ANDROID_TARGET_SDK_VERSION 35
    )
    target_link_libraries(MyApp PRIVATE log)  # Android 必须
endif()
```

**要点：**
- `CMAKE_AUTOMOC ON` 替代 `qt_standard_project_setup()`，避免 Android 兼容问题
- `log` 库必须链接，否则 Android 原生日志调用崩溃
- 不要手写 `android/` 目录，让 Qt 自动生成 AndroidManifest

## 8. 权限请求：放在传输层，和扫描绑定

```cpp
// bluetoothclient.cpp
void BluetoothClient::startScan() {
    requestPermAndScan();   // 先请求权限，拿到后再 doStartScan()
}

void requestPermAndScan() {
    QBluetoothPermission bp;
    if (qApp->checkPermission(bp) == Qt::PermissionStatus::Undetermined) {
        qApp->requestPermission(bp, [this, lp]() {
            // 蓝牙权限拿到后，再查位置权限，串行请求
            if (qApp->checkPermission(lp) == Qt::PermissionStatus::Undetermined)
                qApp->requestPermission(lp, [this]() { doStartScan(); });
            else doStartScan();
        });
        return;
    }
    doStartScan();
}
```

**为什么不在 `main()` 里请求：** Android 权限弹窗是异步的，`main()` 里请求时 UI 还没起来，回调可能丢失。

**为什么不手写 `AndroidManifest.xml`：** Qt 自动生成的清单会根据 `find_package(Qt6 Bluetooth)` 和 target 属性自动加好权限，手写容易和自动生成冲突导致资源合并失败。

## 总结：好改的代码长什么样

| 场景 | 做法 |
|------|------|
| 协议迭代 | 新解析函数 + processBuffer 前面插一行 |
| UI 换版 | 新 Widget + QStackedWidget 加一页 |
| 加新命令 | UI 层发新信号 + 协议层加新函数 + 传输层加 sendXxx() |
| 跨平台 | Qt 抽象好的 API（QFileDialog、QBluetoothPermission）直接用 |
| 第三方依赖 | 尽可能少。这个工程零外部库 |
